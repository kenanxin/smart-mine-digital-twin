## 1. 项目背景与建设目标

### 1.1 顶板灾害管理痛点

- 监测数据碎片化：应力、位移、支架阻力、微震等数据分散，难以形成统一态势。
- 多源融合困难：单一指标难以准确表达顶板灾变演化过程。
- 预警模型适应性不足：阈值式预警容易漏报、误报，缺少趋势和空间联动研判。
- 可视化程度不足：传统曲线和表格难以直观看到风险区域、传播过程和处置对象。
- 管控响应滞后：企业端、监管端、智库端之间缺少统一闭环。

### 1.2 建设目标

- 建设面向煤矿顶板灾变的数字孪生可视化平台。
- 实现顶板应力场、位移场、综合风险场的透明化展示。
- 建立多源监测数据标准接口与融合预警链路。
- 构建企业端、监管端、智库端三端协同管控体系。
- 形成从监测、识别、预警、处置、反馈到复盘的闭环决策能力。

## 2. 整体技术路线

### 2.1 技术路线概述

建议正文写成“感知层、传输层、数据层、模型层、孪生层、应用层、闭环层”七层架构：

1. 感知层：部署顶板应力、顶板离层、顶板下沉、支架阻力、锚杆锚索受力、微震能量等监测设备。
2. 传输层：通过矿用工业环网、5G 专网或井下网关汇聚数据。
3. 数据层：统一数据字段、采样频率、时间戳、测点编码和异常标记。
4. 模型层：调用多源融合风险评估模型，输出风险分值、风险等级、贡献因子和判别依据。
5. 孪生层：在 Three.js 三维巷道和工作面模型中映射传感器、设备和风险云图。
6. 应用层：面向企业端、监管端、智库端提供不同粒度的管控视图。
7. 闭环层：将预警结果转化为处置建议、监管指令、反馈记录和复盘分析。

### 2.2 数据流

可在正文中画图：

```text
多源传感器 -> 边缘网关 -> 标准数据接口 -> 数据清洗与时空对齐
-> 多源融合预警模型 -> 风险分值/等级/解释 -> 三维孪生可视化
-> 企业处置/监管督办/智库优化 -> 反馈数据回流
```

### 2.3 当前原型对应关系

- Three.js 场景：对应数字孪生可视化层。
- ECharts 图表：对应趋势分析与指标展示。
- 顶板六阶段模拟：对应灾变演化和应急闭环演示。
- 三端切换：对应企业、监管、智库协同。
- URL 参数化入口：方便比赛演示和录屏。

## 3. 系统总体架构

### 3.1 架构组成

- 前端展示层：HTML、CSS、JavaScript、Three.js、ECharts。
- 数据服务层：Node.js 本地静态服务和模拟接口。
- 模型服务层：按算法成员提供的风险评估模型输出风险分值、等级和解释字段。
- 数据标准层：统一描述应力、位移、支架阻力、锚索受力、微震等指标。
- 管控业务层：预警研判、处置建议、监管督办、专家复盘。

### 3.2 技术栈

- 三维渲染：Three.js
- 数据图表：ECharts
- 前端运行：原生 HTML/CSS/JavaScript
- 本地服务：Node.js
- 数据组织：标准化 JSON 模拟数据，后续可替换为数据库和真实传感器接口

### 3.3 系统部署形态

- 井下侧：传感器和边缘网关。
- 矿端：企业端实时监控大屏。
- 集团或安监侧：监管端远程管控。
- 高校或科研单位：智库端模型分析与参数优化。

## 6. 监测网络设计

### 6.1 测点布设对象

- 顶板应力测点：布设在运输顺槽、回风顺槽、工作面前方和超前支承压力影响区。
- 顶板离层仪：布设在巷道顶板关键断面。
- 顶板下沉测点：布设在断面中心和两帮交界区域。
- 液压支架阻力传感器：布设在支架立柱或支架控制系统输出端。
- 锚杆锚索受力监测：布设在补强支护关键位置。
- 微震监测：用于识别围岩破裂能量释放。

### 6.2 数据采集频率建议

- 常态监测：10 秒至 1 分钟级采样。
- 预警阶段：提高至秒级或准实时采样。
- 应急阶段：持续上传关键区域数据和处置状态。

### 6.3 测点编码建议

```text
矿井编号-工作面编号-巷道类型-测点类型-序号
示例：M01-WF2301-TRANS-STRESS-004
```

## 7. 监测预警指标与阈值

### 7.1 指标体系

| 指标 | 单位 | 作用 | 风险含义 |
|---|---:|---|---|
| 顶板应力 | MPa | 识别支承压力集中 | 异常升高说明顶板受压集中 |
| 顶板离层 | mm | 识别层间分离 | 持续增大说明围岩结构失稳 |
| 顶板下沉 | mm | 识别巷道变形 | 增长过快说明支护承载不足 |
| 支架阻力 | kN | 判断支架受载 | 异常升高或突降均需关注 |
| 锚索受力 | kN | 判断支护系统状态 | 突变表示支护受力异常 |
| 微震能量 | J | 判断岩体破裂活动 | 能量集中说明破裂活动增强 |

### 7.2 综合风险分值

建议正文口径：

```text
综合风险分值 = 多源指标归一化得分 + 趋势增长项 + 空间联动项 + 模型修正项
```

风险等级建议：

- 0-30：绿色，正常监测。
- 30-50：蓝色或关注，密切观察趋势。
- 50-70：黄色，预警并复核现场。
- 70-85：橙色，高风险处置准备。
- 85-100：红色，停机撤人和封控处置。

说明：具体阈值应在正式报告中结合矿井地质条件、历史数据和算法成员模型结果进行校准。

## 8. 可行性、先进性与应用价值

### 8.1 可行性

- 技术可行：Three.js、ECharts、Node.js 均为成熟技术。
- 数据可行：平台采用标准化多源数据结构，可从模拟数据平滑替换为真实传感器数据。
- 应用可行：三端职责清晰，符合矿端生产、监管督办和科研优化的实际分工。

### 8.2 先进性

- 从单点监测转向多源融合。
- 从二维图表转向三维数字孪生。
- 从被动报警转向可解释预警和处置闭环。
- 从单矿展示转向企业、监管、智库协同。

### 8.3 应用价值

- 提高顶板灾害早期识别能力。
- 降低人工巡检压力和误判风险。
- 缩短预警响应和处置闭环时间。
- 为矿井安全生产、监管督办和科研模型优化提供统一平台。
