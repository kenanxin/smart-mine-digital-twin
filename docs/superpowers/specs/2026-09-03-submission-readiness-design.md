# 项目审查交付加固设计

## 目标

在不新增业务功能的前提下，使线上系统、源码、报告、演示说明和最终提交包保持一致，并为教师现场审查提供可重复、可回退、可验证的演示路径。

## 方案选择

采用“生产地址优先、离线运行兜底、秘密信息独立保存”的方案。相比只维护线上说明，此方案能降低 Render 冷启动或现场网络异常造成的演示风险；相比制作第二套离线系统，它直接复用同一份源码，避免两套实现漂移。

## 交付结构

1. 统一现有 Markdown、README 和两份 Word 报告中的事实口径。
2. 新增教师审查快速指南，集中呈现入口、架构、角色、真实数据证据、演示流程和故障处理。
3. 新增逐分钟演示脚本，覆盖企业端、监管端、智库端、只读端和超级管理员。
4. 新增 Node 预检脚本，检查必需文件、真实数据摘要、测试结果和线上健康状态。
5. 生成白名单式提交包，排除 `.git`、`node_modules`、虚拟环境、环境变量文件、密钥和临时渲染产物。

## 事实口径

- 前端部署于 Vercel，后端部署于 Render，Supabase 提供身份、角色、权限和审计数据持久化。
- 业务角色为企业端、监管端、智库端和只读端；超级管理员负责账户与权限管理。
- 只读端复用智库端布局，但不获得写权限。
- 数据源为老师提供的 20,000 行、11 列 CSV；构建期执行卡尔曼平滑与 XGBoost 推理，运行期通过 RoofRisk API v1 提供结果。
- 演示账户密码不写入 GitHub、报告或提交包，只通过现场私密账户卡提供。

## 故障与安全处理

- Render 冷启动时先访问 `/healthz`，等待服务恢复后再登录。
- Render 重启会使内存会话失效，重新登录即可。
- 线上不可用时使用 Node.js 18+ 在本地启动同一项目。
- 预检只读取文件与 HTTP 状态，不创建账户、不修改权限、不写入生产数据。

## 验收标准

- 文档不再将系统描述为仅本地、仅三账户或未接数据库。
- 文档不含生产密码、Supabase 密钥、Vercel/Render 令牌。
- `npm test` 全部通过，预检脚本给出明确通过/失败结果。
- 两份 DOCX 完成逐页渲染检查，无裁切、重叠、乱码或失效图片。
- 最终压缩包可解压，包含报告、算法代码、运行说明、源码和接口文档，且不包含依赖与秘密文件。
