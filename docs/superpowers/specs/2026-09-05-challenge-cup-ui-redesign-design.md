# 挑战杯答辩级 UI 全局重构设计

## 1. 项目目标

本次重构不是单独美化“当前多源指标”，而是统一登录页、企业端、监管端、专家端和超级管理员后台的视觉语言与信息叙事，使平台适合挑战杯现场答辩和教师审查。

“挑战杯标准”在本设计中指比赛演示级交付质量，而非某项官方 UI 规范。成功标准是：

- 评委在 10 秒内识别当前风险、风险位置和处置状态。
- 评委在 30 秒内理解风险结论来自老师 CSV、XGBoost 结果和多源指标证据。
- 三端职责和闭环关系无需讲解即可区分。
- 界面具有矿业数字孪生辨识度，而不是通用科技大屏模板。
- Google Chrome 中稳定运行，数据更新不影响 Three.js 镜头和页面布局。

## 2. 设计主题

主题名称：**深地层指挥舱**。

视觉依据来自井下巷道、矿灯、钢制设备铭牌、地层测线和工业监控终端。设计应克制、精确、可追溯。Three.js 真实井下场景是品牌主视觉，数据界面为其提供监测证据，不使用无业务含义的光效、渐变球、玻璃卡片或装饰性曲线。

### 2.1 视觉签名

全项目唯一的强记忆点是“地层量程轨”：各指标独立计算 P05-P95 归一化位置，但共享参考区间、当前值游标和越界方向等视觉语法，外观借鉴地层测线和工业标尺。它取代普通进度条，成为企业端、监管端和专家端之间一致的数据语言。

### 2.2 色彩系统

- 深井黑 `#070C10`：页面底色。
- 岩层黑 `#0D151A`：主要工作区。
- 钢板灰 `#162128`：控件和局部抬升层。
- 遥测青 `#35BDCA`：连接、选择、回放游标，不表示安全。
- 矿灯琥珀 `#E9B64B`：关注和一般风险。
- 风险橙 `#F08A45`：较大风险和需要优先复核的偏离状态。
- 灾变红 `#EF6262`：重大风险和必须立即处理的状态。
- 安全绿 `#62B992`：只用于明确的正常状态，不作为大面积装饰。

正常数据以灰白为主。黄色、橙色和红色只在风险偏离时出现，遵循高性能 HMI 的告警显著性原则。

### 2.3 字体系统

- 中文展示标题：`LXGW WenKai Screen`，只用于平台名称和页面级标题，保留地层勘测记录的人工标注感。
- 中文正文与控件：`Microsoft YaHei UI` / `PingFang SC` / `Noto Sans CJK SC`，优先使用本机可用字体。
- 数值、时间、记录编号和哈希：`Chakra Petch` / `Cascadia Mono` / `Consolas`。
- 远程字体资源必须改为项目本地托管并配置 `font-display: swap`，答辩现场断网时字体层级不得失效。
- 标题、正文、说明、数值至少形成四级层级。
- 数值和单位分离，单位字号约为数值的 55%-65%。
- 不使用负字距，不使用随视口宽度连续缩放的字体。

### 2.4 空间、容器与图标系统

- 采用 `4 / 8 / 12 / 16 / 24px` 的间距体系，页面级分区优先使用 `24px`，紧凑控制组使用 `4px` 或 `8px`。
- 卡片圆角限制在 `3-6px`，保持工业终端的精确感；按钮、标签和状态控件不得用夸张胶囊造型。
- 禁止卡片嵌套卡片。内容层级优先通过留白、对齐、字号和单条分隔线表达，减少重复描边和发光外框。
- 删除 emoji 和手绘 SVG 图标，统一使用项目本地托管的 Lucide 图标；图标按钮提供中文工具提示和可访问名称。
- 固定格式的工具栏、量程轨、计数器和图表容器必须使用稳定尺寸或响应式约束，数据更新不得改变其占位。

## 3. 全局信息架构

答辩主叙事固定为：

`井下现场 -> 风险结论 -> 数据证据 -> 模型判断 -> 三端处置闭环`

界面按三个阅读层级组织：

1. 一级总览：风险、位置、时间、是否需要处置。
2. 二级证据：异常指标、阈值、连续趋势和模型概率。
3. 三级追溯：原始记录编号、CSV 时间、设备、标签、预测结果和哈希。

所有端均遵循该层级，但根据角色改变默认焦点。

## 4. 企业端

### 4.1 首屏

首屏保留三列结构，但重新分配视觉权重：

- 左侧：设备状态与关键监测点，减少重复边框和装饰编号。
- 中央：Three.js 井下场景，占首屏主要面积。
- 右侧：当前风险、闭环进度和一条首要处置建议；这里是首屏风险分值的唯一主显示区域。
- 顶部：系统名称、数据在线状态、当前身份和必要操作。
- 底部溯源条：数据源、记录、原始时间、设备和 SHA-256。

首屏不放完整多源指标和历史曲线。右侧风险态势卡是风险分值的唯一主显示区域；Three.js 浮层只显示风险等级、空间位置和触发指标，不重复显示风险分值。两处使用同一条当前记录更新，避免结论不一致。

### 4.2 第二屏：顶板灾变核心监测

第二屏按以下顺序：

1. 风险摘要：当前模型等级、模型证据项数量、统计偏离项数量、连续样本数。
2. 多源风险剖面：七项指标使用统一视觉语法的量程轨，并保持固定业务顺序。
3. 统计参考偏离趋势主图：显示连续历史、100% 参考边界和当前回放游标。
4. 当前记录解释：主要特征证据、XGBoost 结论与处置建议。

多源风险剖面不再使用七张相同小卡片。每一行包含：指标名、当前值、单位、P05、P95、当前位置、状态词和微趋势。七项指标始终按照数据字典中的固定业务顺序显示，回放更新不得改变行位置。当前偏离项在剖面上方的“重点关注”摘要中集中列出，并通过锚点定位到对应固定行。

### 4.2.1 P05-P95 量程语义与算法

P05 和 P95 是老师数据集的统计参考分位数，不等同于国家标准、安全限值或事故阈值。界面统一称为“P05-P95 参考范围”；“超 P95”只描述统计偏离，不直接等同于危险告警。

每项指标独立归一化，禁止把不同单位的原始数值放在同一数值坐标轴上。对有效参考范围 `P95 > P05`：

- 位置比例为 `(当前值 - P05) / (P95 - P05)`。
- `0%-100%` 显示在参考范围内部。
- 低于 P05 时游标停在左边界并显示向左越界箭头和真实偏离倍数。
- 高于 P95 时游标停在右边界并显示向右越界箭头和真实偏离倍数。
- 不用截断后的游标位置替代真实数值，工具提示始终显示原值、单位和分位数。

方向语义由固定指标元数据定义：

- 顶板离层速率、锚杆轴力增量、锚索轴力增量、支架阻力、涌水量和微震能量按“高侧偏离”展示。
- 距水体/岩溶体距离按“低侧接近需关注”展示；负值保留原始符号，不取绝对值伪装成距离。
- 颜色状态优先采用现有 RoofRisk API/XGBoost 风险证据；仅有分位数偏离而没有模型风险证据时标记为“统计偏离”，不得标记为“危险”。

当 `P05 = P95`、参考值缺失、当前值不是有限数或单位未知时，量程轨显示“参考范围不可用”，不计算比例、不显示模拟位置，也不影响其他指标更新。

### 4.2.2 连续偏离趋势口径

原“P95 连续指数”统一更名为“统计参考偏离趋势”。该图展示各指标相对自身 P05-P95 参考范围的多条轨迹，不计算单一综合指数，也不代表 XGBoost 概率或顶板综合风险分。

- 高侧偏离指标采用 `(当前值 - P05) / (P95 - P05) * 100`：`0%` 对应 P05，`100%` 对应 P95，高于 `100%` 表示高侧统计偏离。
- 低侧接近指标采用 `(P95 - 当前值) / (P95 - P05) * 100`：`0%` 对应 P95，`100%` 对应 P05，高于 `100%` 表示低侧统计偏离。
- 图中 `100%` 统一称为“统计参考边界”，不得标注为安全阈值、危险阈值或模型阈值。
- 摘要中的“统计偏离项”同时统计高于 P95 的高侧指标和低于 P05 的低侧指标；模型证据项单独统计，不与其合并。
- 每条轨迹的工具提示显示指标名、原始值、单位、P05、P95、偏离方向和原始时间；不得只显示归一化百分比。
- 当旧接口只返回真实综合风险分历史时，图表标题切换为“综合风险分历史”，纵轴单位切换为“分”，不保留 P05/P95 或 `100%` 参考边界文案。
- 无有效连续指标且无真实风险分历史时显示可操作的空状态，不补零、不沿用上一帧数据。

### 4.3 第三屏：真实数据历史回放

回放区使用“总结带 + 主图 + 风险节点 + 控制条”的结构：

- 总结带显示当前记录、CSV 时间、风险等级、模型结果和置信度。
- 主图为共享时间轴的真实连续趋势。
- 风险节点用于快速定位四类代表记录。
- 控制条包含上一条、播放/暂停、下一条、时间滑块、速度和循环。
- Three.js 只更新风险场和标签，不自动重置或移动相机。

## 5. 监管端

监管端默认回答“哪里需要督办”：

- 首页以区域/矿点风险排序和待督办事件为主。
- 风险分布图、事件队列和闭环时限形成同一阅读路径。
- 显示企业端回传状态，但不展示企业内部操作细节。
- 红色只用于逾期重大风险；一般关注使用琥珀。

## 6. 专家端

专家端默认回答“模型为什么这样判断”：

- 四级概率图是首要模型视图。
- 标准化偏离图明确标注为特征证据，不称为特征贡献。
- 同屏展示真实标签、预测标签、置信度和一致性状态。
- 提供历史相似记录和原始字段，不用装饰性模型动画。

## 7. 登录页与后台

### 7.1 登录页

- 使用项目真实井下场景作为第一视觉信号。
- 登录表单保持简洁，不要求用户选择角色。
- 品牌标题、平台说明、登录表单和服务状态形成明确层级。
- 不新增营销式功能介绍或无业务含义的口号区。

### 7.2 超级管理员后台

- 使用高密度工业表格，而不是大屏卡片布局。
- 重点字段为账号、姓名、角色、状态、最近操作和审计信息。
- 创建账号、重置密码、启停账号采用明确命令和确认状态。
- 当前超级管理员保护规则保持不变。

## 8. 图表规范

- ECharts 图表统一使用项目主题、时间轴、工具提示和 ResizeObserver。
- 图表容器必须有稳定高度，不因加载文案或数据长度发生布局跳动。
- 同一数据在不同图表中的颜色、名称和单位必须一致。
- P05、P95、`100%` 统计参考边界和当前回放位置使用直接标注。
- 不使用 3D 饼图、装饰性仪表盘、雷达图或无法解释的面积填充。
- 大数据回放保持抽样渲染和渐进更新，不重复初始化图表实例。
- 空状态、加载失败和鉴权失败不得显示模拟数值。

## 9. 动效与交互

- 动效只用于回放游标、风险状态变化和必要的图表过渡。
- 状态变化时只强调发生变化的元素，不让整个页面闪烁。
- Three.js 镜头不随数据帧自动跳动。
- 支持 `prefers-reduced-motion`。
- 图标按钮具有工具提示和可见键盘焦点。
- 所有可点击元素满足至少 44px 的稳定交互尺寸，紧凑表格中的行操作除外。
- 风险状态必须同时使用状态文字和形状、图标或位置提示，颜色只作为增强，不得成为唯一判别依据。
- 操作使用语义化 `button` 或链接，表单控件具有可点击标签；异步加载、错误和成功状态通过 `aria-live` 向辅助技术播报。
- 页面提供“跳到主要内容”入口，标题保持层级顺序；所有键盘可操作元素使用清晰的 `:focus-visible` 样式。
- 自动回放提供暂停与复位，不依赖悬停或手势；减少动态效果模式下关闭非必要位移、闪烁和图表过渡。

### 9.1 挑战杯现场演示流程

保留现有“顶板灾变全过程演示”、分阶段场景按钮和复位操作，并将其定义为正式答辩路径：

1. 演示前执行健康检查并预热 Vercel、Render、真实数据接口、Three.js 资源和 ECharts 实例。
2. 一键演示从正常监测开始，依次经过压力升高、离层异常、支架阻力异常、顶板垮落预警和应急处置。
3. 每个阶段使用老师数据集中可追溯的代表记录；界面显示记录编号和原始时间，不生成随机业务数值。
4. 阶段切换只改变当前记录、风险场、告警和闭环状态，不改变用户相机视角。
5. “复位”恢复到固定的正常代表记录、默认井下视角、暂停回放和初始闭环状态，保证重复答辩结果一致。

若真实数据接口不可用，演示按钮进入禁用状态并显示具体错误与重试操作，不回退到伪造数据。现场演示前保留一个已登录的企业端 Chrome 标签页，同时准备登录页作为身份切换入口。

## 10. 响应式布局

### 1920x1080

- 首屏三列完整显示。
- Three.js 为最大视觉区域。
- 第二屏多源风险剖面与主趋势图可同屏形成完整证据链。

### 1366x768

- 保留三列，但压缩辅助说明和次要列表。
- 不压缩数值字号到不可读范围。
- 第二屏允许纵向滚动，不产生横向滚动条。

### 低于 1280px

- Three.js 置顶。
- 决策区、设备区和数据证据区依次堆叠。
- 图表高度固定，文字换行，不发生遮挡。

## 11. 数据与权限约束

- 所有业务数值继续来自现有 RoofRisk API 和老师 CSV 数据集。
- 风险分值继续映射四级运营风险，不伪装成连续模型概率。
- XGBoost 输出继续展示预测类别、四级概率和置信度。
- UI 重构不得修改权限矩阵、登录流程、闭环状态机和原始数据。
- 企业端、监管端、专家端和只读查看者继续使用现有角色策略。

### 11.1 性能预算

- 已缓存的答辩设备上，页面外壳应在 2 秒内可见，Three.js 井下场景应在 5 秒内进入可交互状态。
- Render 冷启动不计入渲染预算，但必须持续显示真实加载状态，并在演示前完成预热。
- `1920x1080` 和 `1366x768` 下，Three.js 稳态目标不低于 30 FPS；连续 30 秒验证期间不得出现持续低于 24 FPS 的区段。
- 回放状态下 ECharts `setOption` 更新频率不超过每秒 5 次，不重复 `echarts.init`，不重复注册 ResizeObserver。
- 图表动画默认不超过 280ms；5 倍速回放时关闭非必要过渡，只更新数据和当前游标。
- 用户点击、滚动和回放控制的主线程响应目标小于 100ms。
- 首屏不得下载第二、第三屏才需要的重复资源；Three.js 高清资源保持现有质量，不以降分辨率作为常规性能方案。

## 13. 测试与验收

自动化测试应覆盖：

- 三端关键容器和角色权限仍存在。
- 图表仅由真实 API 数据更新，无静态模拟回退。
- 多源指标排序、阈值状态和单位映射正确。
- 回放更新不触发 Three.js 相机重新聚焦。
- 企业端页面在 Chrome 中可滚动到第二、第三屏。
- 图表实例正确复用、缩放和响应容器变化。

视觉验收必须在 Google Chrome 中完成：

- `1920x1080` 桌面答辩视口。
- `1366x768` 常见笔记本视口。
- `390x844` 移动视口。
- 首屏品牌、Three.js 和风险结论清晰。
- 第二屏多源风险剖面、统计参考偏离趋势和真实数据来源完整可见。

- Canvas 像素检查确认 Three.js 与 ECharts 均非空白。
- 使用正常、一般、较大、重大四类代表记录逐一确认绿、黄、橙、红语义一致。
- 反复执行两次“一键演示 -> 复位”，确认记录、相机、回放和闭环状态可重复。
