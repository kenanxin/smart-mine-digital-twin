# 挑战杯答辩级 UI 全局重构设计

## 1. 项目目标

本次重构不是单独美化“当前多源指标”，而是统一登录页、企业端、监管端、专家端和超级管理员后台的视觉语言与信息叙事，使平台适合挑战杯现场答辩和教师审查。

“挑战杯标准”在本设计中指比赛演示级交付质量，而非某项官方 UI 规范。成功标准是：

- 评委在 10 秒内识别当前风险、风险位置和处置状态。
- 评委在 30 秒内理解风险结论来自老师 CSV、XGBoost 结果和多源指标证据。
- 三端职责和闭环关系无需讲解即可区分。
- 界面具有矿业数字孪生辨识度，而不是通用科技大屏模板。
- Google Chrome 中稳定运行，数据更新不影响 Three.js 镜头和页面布局。

## 2. 设计主题

主题名称：**深地层指挥舱**。

视觉依据来自井下巷道、矿灯、钢制设备铭牌、地层测线和工业监控终端。设计应克制、精确、可追溯。Three.js 真实井下场景是品牌主视觉，数据界面为其提供监测证据，不使用无业务含义的光效、渐变球、玻璃卡片或装饰性曲线。

### 2.1 视觉签名

全项目唯一的强记忆点是“地层量程轨”：使用共享 P05-P95 坐标、当前值游标和越界方向表达多源指标，外观借鉴地层测线和工业标尺。它取代普通进度条，成为企业端、监管端和专家端之间一致的数据语言。

### 2.2 色彩系统

- 深井黑 `#070C10`：页面底色。
- 岩层黑 `#0D151A`：主要工作区。
- 钢板灰 `#162128`：控件和局部抬升层。
- 遥测青 `#35BDCA`：连接、选择、回放游标，不表示安全。
- 矿灯琥珀 `#E9B64B`：关注和一般风险。
- 灾变红 `#EF6262`：重大风险和必须立即处理的状态。
- 安全绿 `#62B992`：只用于明确的正常状态，不作为大面积装饰。

正常数据以灰白为主。黄色、橙色和红色只在风险偏离时出现，遵循高性能 HMI 的告警显著性原则。

### 2.3 字体系统

- 中文标题与正文：优先使用项目现有、加载稳定的中文无衬线字体。
- 数值、时间、记录编号和哈希：`Chakra Petch` / `Cascadia Mono` / `Consolas`。
- 标题、正文、说明、数值至少形成四级层级。
- 数值和单位分离，单位字号约为数值的 55%-65%。
- 不使用负字距，不使用随视口宽度连续缩放的字体。

## 3. 全局信息架构

答辩主叙事固定为：

`井下现场 -> 风险结论 -> 数据证据 -> 模型判断 -> 三端处置闭环`

界面按三个阅读层级组织：

1. 一级总览：风险、位置、时间、是否需要处置。
2. 二级证据：异常指标、阈值、连续趋势和模型概率。
3. 三级追溯：原始记录编号、CSV 时间、设备、标签、预测结果和哈希。

所有端均遵循该层级，但根据角色改变默认焦点。

## 4. 企业端

### 4.1 首屏

首屏保留三列结构，但重新分配视觉权重：

- 左侧：设备状态与关键监测点，减少重复边框和装饰编号。
- 中央：Three.js 井下场景，占首屏主要面积。
- 右侧：当前风险、闭环进度和一条首要处置建议。
- 顶部：系统名称、数据在线状态、当前身份和必要操作。
- 底部溯源条：数据源、记录、原始时间、设备和 SHA-256。

首屏不放完整多源指标和历史曲线。风险卡不重复显示相同分值，避免 Three.js 浮层与右侧栏信息竞争。

### 4.2 第二屏：顶板灾变核心监测

第二屏按以下顺序：

1. 风险摘要：当前等级、异常数量、超 P95 数量、连续样本数。
2. 多源风险剖面：七项指标共享量程轨，异常项目置顶。
3. P95 连续指数主图：显示连续历史、100% 阈值线和当前回放游标。
4. 当前记录解释：主要特征证据、XGBoost 结论与处置建议。

多源风险剖面不再使用七张相同小卡片。每一行包含：指标名、当前值、单位、P05、P95、当前位置、状态词和微趋势。正常行保持低对比，关注和危险行使用琥珀或红色并自动排在前面。

### 4.3 第三屏：真实数据历史回放

回放区使用“总结带 + 主图 + 风险节点 + 控制条”的结构：

- 总结带显示当前记录、CSV 时间、风险等级、模型结果和置信度。
- 主图为共享时间轴的真实连续趋势。
- 风险节点用于快速定位四类代表记录。
- 控制条包含上一条、播放/暂停、下一条、时间滑块、速度和循环。
- Three.js 只更新风险场和标签，不自动重置或移动相机。

## 5. 监管端

监管端默认回答“哪里需要督办”：

- 首页以区域/矿点风险排序和待督办事件为主。
- 风险分布图、事件队列和闭环时限形成同一阅读路径。
- 显示企业端回传状态，但不展示企业内部操作细节。
- 红色只用于逾期重大风险；一般关注使用琥珀。

## 6. 专家端

专家端默认回答“模型为什么这样判断”：

- 四级概率图是首要模型视图。
- 标准化偏离图明确标注为特征证据，不称为特征贡献。
- 同屏展示真实标签、预测标签、置信度和一致性状态。
- 提供历史相似记录和原始字段，不用装饰性模型动画。

## 7. 登录页与后台

### 7.1 登录页

- 使用项目真实井下场景作为第一视觉信号。
- 登录表单保持简洁，不要求用户选择角色。
- 品牌标题、平台说明、登录表单和服务状态形成明确层级。
- 不新增营销式功能介绍或无业务含义的口号区。

### 7.2 超级管理员后台

- 使用高密度工业表格，而不是大屏卡片布局。
- 重点字段为账号、姓名、角色、状态、最近操作和审计信息。
- 创建账号、重置密码、启停账号采用明确命令和确认状态。
- 当前超级管理员保护规则保持不变。

## 8. 图表规范

- ECharts 图表统一使用项目主题、时间轴、工具提示和 ResizeObserver。
- 图表容器必须有稳定高度，不因加载文案或数据长度发生布局跳动。
- 同一数据在不同图表中的颜色、名称和单位必须一致。
- P05、P95、100% 阈值和当前回放位置使用直接标注。
- 不使用 3D 饼图、装饰性仪表盘、雷达图或无法解释的面积填充。
- 大数据回放保持抽样渲染和渐进更新，不重复初始化图表实例。
- 空状态、加载失败和鉴权失败不得显示模拟数值。

## 9. 动效与交互

- 动效只用于回放游标、风险状态变化和必要的图表过渡。
- 状态变化时只强调发生变化的元素，不让整个页面闪烁。
- Three.js 镜头不随数据帧自动跳动。
- 支持 `prefers-reduced-motion`。
- 图标按钮具有工具提示和可见键盘焦点。
- 所有可点击元素满足至少 44px 的稳定交互尺寸，紧凑表格中的行操作除外。

## 10. 响应式布局

### 1920x1080

- 首屏三列完整显示。
- Three.js 为最大视觉区域。
- 第二屏多源风险剖面与主趋势图可同屏形成完整证据链。

### 1366x768

- 保留三列，但压缩辅助说明和次要列表。
- 不压缩数值字号到不可读范围。
- 第二屏允许纵向滚动，不产生横向滚动条。

### 低于 1280px

- Three.js 置顶。
- 决策区、设备区和数据证据区依次堆叠。
- 图表高度固定，文字换行，不发生遮挡。

## 11. 数据与权限约束

- 所有业务数值继续来自现有 RoofRisk API 和老师 CSV 数据集。
- 风险分值继续映射四级运营风险，不伪装成连续模型概率。
- XGBoost 输出继续展示预测类别、四级概率和置信度。
- UI 重构不得修改权限矩阵、登录流程、闭环状态机和原始数据。
- 企业端、监管端、专家端和只读查看者继续使用现有角色策略。

## 12. 实施边界

本次允许修改：

- 页面布局和语义结构。
- CSS 设计令牌与组件样式。
- ECharts 配置、图表组合和数据标注。
- 前端数据排序、格式化和响应式行为。
- 加载、空状态和错误状态文案。

本次不修改：

- 真实数据文件内容。
- XGBoost 预计算结果。
- 后端业务接口语义。
- Supabase 认证与账号权限模型。
- Three.js 矿井拓扑和高清资源。

## 13. 测试与验收

自动化测试应覆盖：

- 三端关键容器和角色权限仍存在。
- 图表仅由真实 API 数据更新，无静态模拟回退。
- 多源指标排序、阈值状态和单位映射正确。
- 回放更新不触发 Three.js 相机重新聚焦。
- 企业端页面在 Chrome 中可滚动到第二、第三屏。
- 图表实例正确复用、缩放和响应容器变化。

视觉验收必须在 Google Chrome 中完成：

- `1920x1080` 桌面答辩视口。
- `1366x768` 常见笔记本视口。
- `390x844` 移动视口。
- 首屏品牌、Three.js 和风险结论清晰。
- 第二屏多源风险剖面、P95 主图和真实数据来源完整可见。
- 数据播放 30 秒期间无布局跳动、文字重叠和相机跳动。
- Canvas 像素检查确认 Three.js 与 ECharts 均非空白。

## 14. 交付顺序

1. 建立全局设计令牌与基础组件规范。
2. 重构企业端第二、第三屏的数据证据链。
3. 收敛企业端首屏的信息层级。
4. 统一监管端和专家端的角色化表达。
5. 收口登录页和超级管理员后台。
6. 执行完整测试、Chrome 多视口截图、可用性审查和生产部署。
