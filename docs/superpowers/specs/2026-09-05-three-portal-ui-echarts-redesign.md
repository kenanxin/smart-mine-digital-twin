# 三端 UI 与 ECharts 数据表达重设计规格

## 目标

在不削弱现有 Three.js 井下场景画质、鉴权和闭环业务的前提下，将企业端、监管端、专家端重构为同一工业设计体系下的三种任务工作台。所有业务数值来自现有 RoofRisk API 或其数据集元信息，不再在图表层制造模拟时间、趋势、事件数量或同步时间。

## 设计方向

采用“统一工业设计系统 + 三端差异化工作台”。界面服务于矿山值守、监管督办和模型研判，不使用营销式大标题、装饰性渐变、悬浮页面卡片或无业务含义的动画。

视觉语言取自井下监测设备：石墨黑 `#0b1115`、设备钢 `#151e24`、分隔线 `#2b3941`、遥测青 `#32c7d9`、注意黄 `#f2b84b`、安全绿 `#50c878`、重大风险红 `#f05b5b`。正文优先使用系统中文黑体，数字和编号使用等宽字体。卡片圆角不超过 6px，所有间距、颜色、边框和字号由 CSS token 统一管理。

唯一的视觉签名是“监测刻度轨”：企业端的真实指标、趋势阈值和场景测点使用同一套刻度、状态色和编号，让二维数据能与三维巷道中的设备建立直观对应。

## 共享外壳

- 顶栏保留平台名、当前角色、用户身份、系统连接状态与退出入口，不提供角色切换。
- 主视图以角色决定布局，不通过 URL 参数提升权限；`viewer` 复用专家端只读布局。
- 数据来源条持续显示源文件名、记录 ID、原始时间、设备 ID、数据量和哈希摘要。没有 API 时间时不显示虚构“刚刚同步”。
- 所有交互按钮具有明确动词、键盘焦点和禁用态；只读角色不展示可执行闭环动作。
- 所有面板支持 `loading`、`empty`、`partial`、`success`、`error` 五种状态。请求失败时清除旧数据并提供可执行的重试入口或检查提示。

## 企业端

### 单一任务

值守人员在井下场景中定位异常测点，判断风险等级，并推进处置闭环。

### 布局

- 桌面端采用“左侧实时指标轨 / 中央 Three.js 场景 / 右侧风险与处置轨”，底部为趋势和数据来源。
- 中央场景始终是最大区域，保留现有纹理、HDR、模型和像素比策略；UI 不使用滤镜或缩放截图替代实时场景。
- 左侧显示七项真实指标：值、单位、状态、P05-P95 参考区间和相对位置。负距离等真实异常值原样呈现并标识数据状态，不自行修正。
- 右侧显示综合风险指数、预测等级、置信度、主要触发项、处置指令和闭环步骤。

### 图表

- “阈值归一趋势”使用 ECharts 时间轴折线图。每个指标显示 `value / p95 * 100` 的阈值指数，100 为参考线；tooltip 同时显示原始值、单位和原始时间。
- 不把不同量纲原值直接画在同一 Y 轴，也不使用面积堆叠制造总量含义。
- 默认展示对当前风险最关键的 3 至 4 项指标，用户可通过图例切换，图例状态由图表实例保留。

## 监管端

### 单一任务

监管人员按优先级审阅真实风险事件、查看证据和处置进度，并进行督办复核。

### 布局

- 左侧为事件队列，按重大风险、较大风险、一般风险、低风险及分数排序。
- 中部为选中事件详情、风险分布和处置证据。
- 右侧为闭环进度、责任方、当前步骤、企业反馈与专家意见。
- Three.js 仅作为事件空间定位的辅助视图，不挤压队列和督办操作。

### 图表

- 风险等级分布使用横向条形图，展示真实事件数量并同时显示绝对值与占比。
- 闭环完成情况使用分段进度和状态数字，不使用装饰性仪表盘。
- 事件趋势仅在 API 提供多个真实时间点时显示；没有足够时间序列时显示“暂无连续历史”，不得生成日期和数量。

## 专家端

### 单一任务

专家核对模型预测、真实标签、指标偏离、历史变化和证据来源，形成可解释结论。

### 布局

- 顶部展示预测等级、真实等级、一致性、置信度和综合风险指数。
- 中部并列显示四分类概率、标准化偏离排序和多指标历史对比。
- 底部显示规则层、融合层、闭环层解释，以及完整来源与模型字段说明。

### 图表

- 四分类概率使用水平概率条，不使用在单一类别接近 100% 时缺乏比较价值的环形图。
- 指标解释称为“标准化偏离”或“阈值偏离”，除非后端提供 SHAP 等真实解释值，不称“特征贡献”。
- 多指标历史对比复用阈值指数；tooltip 显示各自原始量纲。
- 预测与真实标签不一致时使用清晰的警告状态，并保留两者原始文本。

## ECharts 架构与数据契约

- 保留当前原生 ECharts 6 集成，不增加框架包装器。
- `js/charts.js` 只负责主题注册、实例生命周期、option 构建和数据更新；业务 API 请求与权限仍由 `js/main.js` 管理。
- 每个 DOM 最多一个实例。初始化前验证容器非零尺寸，隐藏角色门户在显示后再初始化或执行 resize。
- 用共享 `ResizeObserver` 监听图表容器，不只依赖 `window.resize`；页面卸载时 disconnect 并 dispose。
- 结构变化使用 `notMerge: true`，仅数据变化使用默认 merge。时间序列使用 `xAxis.type = 'time'` 和真实时间戳。
- 共享表格型数据优先使用 `dataset` 和 `encode`。tooltip 使用 `renderMode: 'richText'`，不把 API 文本插入 HTML。
- 图表主题统一注册一次，公共数字、单位、时间和状态格式化集中管理。
- 浏览器路径统一使用 Canvas renderer。当前数据规模以历史 API 返回上限为准；时间序列启用 `sampling: 'lttb'`，默认关闭逐点 symbol。

### 输入

- `/api/roof-risk/current`：当前记录、风险、概率、指标、来源与闭环。
- `/api/roof-risk/history`：真实时间序列。
- `/api/roof-risk/events`：监管事件队列与等级分布。
- `/api/roof-risk/explain`：解释字段；只有明确的解释算法输出才能使用“贡献”措辞。

### 禁止项

- 图表代码中不得出现硬编码业务日期、告警数量、产量、风险趋势或随机数。
- 不将演示阶段数据混入真实 API 图表。演示按钮可改变 Three.js 灾变阶段，但必须明确标记为“演示”，且真实数据来源条保持不变。
- 不基于客户端当前时间生成同步状态。

## 响应式行为

- `>= 1280px`：企业端三轨布局；监管和专家端保持队列/分析/行动并列。
- `768px-1279px`：场景保持首屏主体，右侧行动区紧随场景，图表改为两列或单列，不能被埋到长页面末端。
- `< 768px`：顶栏紧凑化，角色信息换行；面板单列；场景保持稳定宽高比；表格转为可扫描列表；按钮最小触控高度 44px。
- 所有固定格式组件定义稳定高度或 `aspect-ratio`，数据加载和长文本不得推动相邻布局跳动或重叠。

## 可访问性与动效

- 状态不只依赖颜色，同时显示文字或图标。
- 键盘可访问事件队列、图例替代控件和处置按钮，焦点轮廓清晰。
- 尊重 `prefers-reduced-motion`；仅保留数据更新和面板状态变化所需的短过渡。

## 测试与验收

- 单元测试验证真实数据到图表 dataset 的映射、时间轴、单位、P95 归一、概率顺序、风险分组以及无硬编码模拟数据。
- 回归测试验证三端鉴权、闭环权限、API 和 Three.js 配置保持通过。
- 浏览器分别以企业、监管、专家账户检查桌面、平板和手机视口；无重叠、横向溢出或空白图表。
- 捕获并检查 `console.error`、`pageerror` 和失败资源；任何 ECharts 注册或零尺寸错误均判失败。
- 验证容器尺寸变化会触发 chart resize，门户切换/登录后不会重复 init；tooltip 中的恶意标签以纯文本呈现。
- 验证页面滚轮在图表上仍能滚动页面，不使用吞噬滚轮的 inside dataZoom。
- 最终运行完整测试和提交预检，推送 `main` 后确认 Vercel 生产构建成功。
