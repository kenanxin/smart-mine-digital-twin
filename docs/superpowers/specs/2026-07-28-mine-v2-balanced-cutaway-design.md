# 智慧矿山第二代一体化剖切场景设计

## 1. 目标与范围

本设计面向成员4的数字孪生前端任务，重建中央 Three.js 场景，使首屏在构图、尺度、空间纵深、工业密度和光照关系上接近用户提供的智慧矿山参考图，同时保持地下煤矿顶板预警业务逻辑成立。

本轮只重建第二代三维场景及其数据适配边界，不迁移 Vue3，不重做整套业务界面，不实施最终设备精模。旧场景继续保留，第二代场景验收前不替换现有入口。

参考图控制以下视觉关系：

- 上部为大范围地表矿区；
- 中部为连续岩体及地层剖切过渡；
- 下部为嵌入岩体的多层地下巷道；
- 工业设施、车辆、矿灯和业务标签形成真实生产密度；
- 默认镜头同时读出地表规模与地下纵深。

地表不照搬参考图中的大型露天矿坑。按已确认方案，使用山谷台地、地下煤矿工业广场、矿区道路和井口系统获得相近的规模感，避免与顶板灾变预警主题产生生产逻辑冲突。

## 2. 已确认决策

- 主构图：均衡一体剖切；
- 首屏比例：地表约 44%，岩层过渡约 8%，地下约 48%；
- 地表逻辑：山谷台地混合矿区；
- 地下逻辑：三个生产水平和一个核心工作面；
- 重建方式：新建第二代场景模块，复用稳定的材质、设备注册、模拟数据和灾害接口；
- 界面策略：保留当前功能和数据挂点，场景通过后再向参考图调整视觉布局；
- 数据策略：当前由前端模拟器生成，后续通过适配层切换到真实接口。

## 3. 空间尺度与坐标

统一采用 `1 Three.js 单位 = 1 米`。

- 可视矿区范围：约 900m x 520m；
- 地下可视深度：约 210m；
- 第一生产水平：约 -45m；
- 第二生产水平：约 -95m；
- 第三生产水平：约 -155m；
- 核心工作面：约 140m 长，采用真实巷道和设备比例；
- 主要巷道净宽按 4.5m 至 6.5m 建模；
- 车辆、轨道、皮带、支护和硐室尺寸均服从同一米制比例。

世界坐标以地表工业广场附近为原点。地表高度通过地形函数或高度场计算；地下点位通过巷道中心线、断面和里程计算，禁止为适配镜头随意缩放单个设备。

## 4. 总体场景结构

第二代场景固定使用独立目录 `js/scene/mine-v2/`，由以下单元组成：

- `mine-v2.js`：场景装配、运行时对象和公开 API；
- `terrain.js`：山地、台地、道路基础和地表高度查询；
- `cutaway-geology.js`：连续岩体、煤层和剖切窗口；
- `roadway-network.js`：巷道中心线、断面挖空、主斜井和联络巷；
- `surface-campus.js`：井口、工业广场、洗选转运和输煤设施；
- `working-face.js`：1206 工作面、顺槽和核心设备挂点；
- `monitor-layout.js`：依据拓扑生成监测点和业务锚点；
- `camera-presets.js`：总览、地表、地下、工作面四个镜头；
- `scene-adapter.js`：旧设备注册、模拟数据、灾害效果和 UI 接口适配。

每个单元只负责一个空间或业务边界。公开对象使用稳定名称，灾害和交互模块不得依赖子网格顺序。

## 5. 地表矿区

地表由连续山体、山谷台地、工业广场和道路系统组成：

- 远景为连续山脊和大气透视，不使用孤立背景墙；
- 中景用两至三级自然台地形成参考图式层次，但不形成完整露天采坑；
- 工业广场位于画面右中部，包含井口、洗选转运建筑、栈桥和辅助厂房；
- 一条主服务道路和一条运输道路形成可解释闭环；
- 井口与主斜井在同一坐标系连续连接；
- 地表车辆严格沿道路曲线运动，速度保持矿区低速范围；
- 地形、道路和建筑均与地面接触，不允许悬浮或穿插。

本阶段复用现有车辆作为尺度参照并放置在中远景。未达到近景质量门槛的车辆不得成为主镜头视觉中心。

## 6. 连续岩体与剖切方式

地下系统必须嵌入完整岩体。剖切只移除靠近主镜头的一部分地质体，形成不规则观察窗口：

- 岩体包围巷道顶部、侧帮和后方；
- 巷道向剖切窗口后方继续延伸并产生透视消失；
- 地层变化通过岩体内部材质和局部煤层表达；
- 不使用整齐长方体地层板、悬空平台或统一深度的墙面开孔；
- 剖切边缘使用不规则几何、碎石和接触阴影消除模型切片感；
- 不建立覆盖整个地下的巨大开放洞穴。

巷道可以为视觉展示适度扩大剖切开口，但真实断面尺寸保持不变。

## 7. 三层地下拓扑

地下采用一条主斜井、三个生产水平和必要联络系统：

### 第一水平

- 主斜井入口与井口连续；
- 设置主要运输巷和人员通道；
- 作为地表与深部系统的过渡层。

### 第二水平

- 设置辅助运输巷、回风巷和联络巷；
- 布置中央变电硐室和泵房；
- 允许列车或胶轮车作为中景动态对象。

### 第三水平

- 设置工作面运输顺槽、回风顺槽和必要联络巷；
- 布置 1206 核心工作面；
- 液压支架、采煤机、刮板输送机和转载系统在设备精模阶段完善。

主斜井按真实坡度连接三个水平。联络巷必须在几何和业务上真正贯通，禁止仅在正视图中相交。

## 8. 镜头、标签与交互

提供四个稳定镜头预设：

- 总览：恢复 44/8/48 一体剖切主构图；
- 地表：聚焦工业广场、道路和井口，保留少量剖切边缘；
- 地下：聚焦三层主干网络，仍保留岩体包裹关系；
- 工作面：聚焦 1206 工作面及顶板监测区域。

默认镜头不自动旋转。轨道控制器限制极角、方位角、缩放范围和目标位置，避免用户旋转到会破坏剖切表达的背面。

总览只显示 8 至 10 个关键标签；进入局部镜头后再展开设备、传感器和人员定位标签。标签采用屏幕空间避让，点击后镜头平滑聚焦，并向现有 UI 发布选中对象信息。

## 9. 监测点生成规则

现有 `MONITOR_POINTS` 是为旧场景手工编写的模拟点，坐标和分类不直接沿用。第二代监测点依据巷道拓扑和风险位置生成：

- 点位坐标由巷道中心线、里程、断面顶点和工作面锚点计算；
- 顶板压力、离层、下沉、巷道表面位移和支架阻力分别建模；
- 工作面、顺槽、回风侧、巷道交叉口、深部区段和硐室入口为优先布置区域；
- 摄像头、人员定位和设备状态单独分类，不计入顶板传感器数量；
- 每个点包含唯一编号、类型、位置说明、三维坐标、单位、阈值、当前值、趋势和风险等级；
- 点位数量由场景配置产生，面板统计直接从同一注册表聚合。

所有阈值和数据明确标记为比赛模拟数据，不宣称为生产安全标准。后续真实布点资料通过配置替换，不修改场景几何 API。

## 10. 数据流与模拟器

统一状态流为：

`模拟器/未来接口 -> 状态适配层 -> 设备与监测注册表 -> Three.js、图表、面板和预警弹窗`

模拟器使用连续时间函数、缓慢漂移、受控噪声和可重复随机种子，避免数值逐帧无规律跳动。设备总数、运行状态、监测点数量、风险等级和三维对象全部从注册表派生。

未来接口通过 REST 初始化和 WebSocket 增量更新接入。接口缺失时继续使用模拟器；单个对象数据异常时只降级该对象，不让整个三维画布空白。

## 11. 界面继承边界

当前顶部标题、左右面板、中央画布、图表、预警和灾害触发功能保留。第二代场景通过现有挂点接入，不在本轮同时迁移 Vue3。

场景结构验收后，界面再向参考图调整：

- 扩大中央三维画面；
- 缩窄左右面板并提高信息密度；
- 增加顶部导航和底部功能栏；
- 统一参考图式边框、标签和层级；
- 保留现有数据 DOM 标识或提供兼容映射。

视觉改造不得造成面板数据与场景对象不一致。

## 12. 材质与照明

- 复用现有合法授权的岩石、地面、金属纹理和 HDRI；
- 重新校正纹理实际尺寸，避免岩壁纹理过大或重复明显；
- 岩石、煤层、道路、混凝土、钢材、橡胶和锈蚀使用独立 PBR 参数；
- 地表采用太阳光、天空环境和空气透视；
- 地下采用低环境光、暖色矿灯、设备灯和少量冷色功能光；
- 地表与地下分别校正曝光，但在总览中保持自然过渡；
- 使用接触阴影和环境遮蔽强化设备接地及巷道体积；
- 不用过强 Bloom、纯黑洞口或均匀泛光掩盖几何问题。

## 13. 性能与降级

目标是在 1920x1080 桌面大屏布局下保持不低于 40 FPS 的稳定交互。

- 重复支护、轨枕、矿灯和管线使用实例化；
- 地形、远景建筑和远端巷道使用 LOD；
- 阴影只覆盖主镜头重要区域；
- 限制设备精模和高分辨率纹理的近景使用范围；
- 资源失败采用局部占位材质或隐藏非关键对象；
- 任何降级不得改变设备统计、监测点坐标或道路接地关系。

## 14. 验收标准

### 视觉

- 首屏明显接近参考图的上地表、中过渡、下地下构图；
- 地表矿区具有大面积、连续山体、道路和工业设施；
- 地下三层巷道具有纵深、弯曲和真实连通关系；
- 巷道被岩体包裹，不出现墙面开孔、悬空平台或巨大洞穴；
- 默认镜头能识别井口、三个水平、两个硐室和一个完整工作面；
- 岩石、道路和工业材质具有非纯色细节，暗部仍可读。

### 数据一致性

- 设备总数等于注册场景对象数；
- 监测点数量等于拓扑生成点数；
- 摄像头和人员不计入顶板传感器数量；
- 标签、面板、图表和预警使用同一状态源；
- 模拟数据带有明确说明且可重复生成。

### 交互与技术

- 四个镜头预设连续切换 10 次不出现空白；
- 桌面和窄屏截图无 UI 重叠；
- 执行画布非空像素检查；
- 检查道路与车辆接触、巷道贯通、标签锚点和设备穿模；
- 记录首屏加载时间、平均 FPS、可见三角面数和资源失败情况；
- 旧场景在第二代场景验收前仍可运行和恢复。

## 15. 实施顺序

1. 建立第二代模块和米制坐标约束；
2. 完成地表高度场、连续岩体和剖切窗口；
3. 完成主斜井、三层巷道和真实贯通；
4. 完成工业广场、道路和井口连接；
5. 接入镜头、标签和旧运行时适配层；
6. 依据拓扑生成监测点并接入模拟器；
7. 执行构图、接地、连通、数据一致性和性能验收；
8. 场景结构通过后进入设备精模和界面视觉统一阶段。
