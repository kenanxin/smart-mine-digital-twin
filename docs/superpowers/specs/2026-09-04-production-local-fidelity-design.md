# 生产环境与本地场景画质一致化设计

## 目标

Vercel 生产环境必须加载与本地开发环境相同的原始三维资源，使地表与井下场景在材质、环境光照、模型细节和渲染参数上保持一致。不得通过降低 HDR 分辨率、压缩纹理或替换低精度模型来缩短加载时间。

## 问题原因

当前 HDR、PBR 纹理和 GLB 模型由 Git LFS 管理。Vercel 的 Git 构建得到的是 LFS 指针文本而不是二进制资源，因此运行时无法解析 HDR、纹理和模型。场景虽可通过基础光照和程序化模型继续运行，但视觉效果低于本地环境。

## 方案

将浏览器运行时实际请求的高清资源从 Git LFS 迁移为普通 Git 文件，并继续由 Vercel 作为同域静态文件发布。仅迁移运行时依赖，不迁移模型源文件、未使用资产、授权文档或比赛报告。

运行时资源范围：

- `assets/hdri/quarry_02_4k.hdr`；
- `assets/textures/` 下 `TEXTURE_ASSETS` 注册的六套 PBR 材质，共 18 张纹理；
- `focused-longwall.js` 实际加载的输送机和 CCTV 优化 GLB。

上述范围共 21 个文件，约 59.67 MB。当前代码未调用其余模型资源，因此不纳入本次迁移。

迁移通过精确的 `.gitattributes` 例外规则实现。资源 URL 和 Three.js 渲染参数保持不变，因此本地和线上使用相同字节内容，不引入第二套画质配置。

## 加载与降级

正常路径继续加载原始 4K HDR、PBR 纹理和精细 GLB。现有 HDR 文件头校验、基础光照回退、纹理回退和程序化设备回退继续保留，防止资源网络异常导致整个场景不可用。降级只作为异常保护，不作为生产环境的正常显示路径。

## 验证

实施后必须完成以下检查：

1. Git 对运行时资源存储真实二进制内容，而不是 LFS 指针。
2. Vercel 资源响应具有正确文件大小和文件签名。
3. 生产环境不出现 HDR、纹理或 GLB 解析错误。
4. Three.js 画布非空，场景报告就绪，并具有有效网格和三角形计数。
5. 地表与井下视角切换正常，材质、环境光照和精细设备模型与本地一致。
6. 全量自动化测试与真实数据离线预检通过。

## 交付

所有改动提交到 `main` 并推送 GitHub，等待 Vercel Production 部署为 `Ready` 后在正式域名复验。预计首次加载需要下载约 59.67 MB，用户已接受约 10 至 30 秒的首次等待时间。
