# 橙色预警三端协同闭环演示设计

## 目标

在同一台演示电脑上，通过依次登录企业端、监管端和智库端，完整展示一次由老师真实 CSV 样本及 XGBoost 多元融合结果触发的橙色预警，并完成现场处置、监管核验、机理分析和案例归档。三个账号共享同一个浏览器事件状态，切换账号后流程不断档。

## 方案选择

### 方案 A：沿用服务端内存进度

改动最少，但 Render 休眠或重启会丢失状态，现有 `advance/reset/archive` 也无法表达工单、照片、驳回与复提，不满足演示可靠性要求。

### 方案 B：完整 Supabase 工作流

可支持跨电脑实时协同和长期保存，但需要增加数据库表、Storage bucket、RLS 和部署迁移。本次明确为同一电脑演示，引入这些环节会增加现场失败点。

### 方案 C：本地优先演示状态，复用真实数据与现有服务（采用）

事件 JSON 和工单保存在 `localStorage`，照片保存在 `IndexedDB`；真实监测、XGBoost 结果、相似案例来自现有数据 API，专家建议继续调用现有服务端 DeepSeek 接口。该方案在同一浏览器跨账号稳定共享，Render 休眠不影响已完成步骤，且不伪造老师数据。

## 真实数据边界

- 预警触发记录固定使用 `REC-202511101149-02909`，来源为 `teacher_roof_monitoring.csv`，设备为“监测1”，真实标签与预测标签均为“较大风险”，风险分 70，模型置信度约 99.98%。
- 核验对照记录使用同设备 4 分钟后的 `REC-202511101153-02911`，真实标签与预测标签均为“一般风险”，风险分 45。
- 页面使用“预警触发真实记录”和“后续监测真实对照”措辞，不把两条记录之间的变化宣称为真实工程措施的因果效果。
- 现场工单、补强支护说明、整改意见和上传照片均标注为“现场演示记录”。
- DeepSeek 不可用时仍可展示本地专家规则，但必须明确显示来源，不能伪装为 AI 返回。

## 事件状态机

事件采用七个确定状态，同一时间只有一个状态有效：

1. `ready`：演示尚未开始。
2. `alert_triggered`：橙色预警已触发，等待企业确认。
3. `disposal_in_progress`：企业填写补强支护措施、工单和现场照片。
4. `pending_review`：企业已提交，等待监管核验。
5. `changes_requested`：监管驳回，企业根据整改意见补充后再次提交。
6. `verified`：监管核验通过，等待智库归档。
7. `archived`：智库确认闭环并纳入演示案例库。

允许的动作和责任端：

- 企业端：启动演示、确认预警、提交处置、整改后复提、重置演示。
- 监管端：填写核验意见后通过，或填写整改意见与期限后驳回。
- 智库端：生成专家建议、查看相似案例、在监管通过后纳入案例库。
- 非责任端只能查看当前状态和时间线，不能越级推进。

所有动作写入时间线，包含动作名称、角色、显示名称、时间和说明。状态读取时校验版本与枚举值，损坏数据自动回到 `ready`，但不会删除 IndexedDB 中其他无关数据。

## 三端界面

### 公共演示入口

现有顶部灾变工具栏增加“橙色预警演示”入口和当前事件状态。企业端可启动或重置；监管端、智库端显示只读状态。页面不自动循环推进，防止演示过程失控。

### 企业端

- 启动后出现一次橙色系统预警弹窗，显示真实记录编号、70 分、模型概率、前三项特征证据及井下热点入口。
- “进入处置”打开独立处置抽屉，不挤压 Three.js 首屏。
- 处置表单要求填写补强支护措施、工单编号、负责人和完成时间，并至少上传一张照片后才能提交。
- 照片显示缩略图、文件名和上传时间；限制 JPEG/PNG/WebP、单张不超过 5 MB、最多 4 张。
- 提交后表单只读，显示“等待监管核验”；被驳回后重新开放并突出整改意见。

### 监管端

- 登录后在驾驶舱顶部显示橙色督办横幅，不采用遮挡数据的持续弹窗。
- 核验面板显示企业是否处置、工单字段、照片缩略图、提交时间和整改时限。
- 用并列指标展示“预警触发真实记录”和“后续监测真实对照”，同时显示数据来源与时间差。
- “核验通过”和“驳回整改”都要求填写意见；驳回还必须填写整改期限。
- 核验动作后立即更新三端共享状态和事件时间线。

### 智库端

- 现有科研分析大屏增加“当前预警事件”条带，将风险等级、记录编号、闭环状态与现有图表关联。
- 风险机理卡显示模型四分类概率、特征贡献和主要因素组合，不新增随机数据。
- 相似案例通过七项标准化特征的欧氏距离从 20,000 条真实记录中检索最接近的 3 条，展示记录编号、时间、标签、风险分和相似度；相似度仅表示特征距离，不表示事故结论。
- 专家建议继续复用 `POST /api/roof-risk/expert-advice`，并把当前演示状态、企业措施和监管意见纳入请求摘要。
- 只有监管核验通过后才能“纳入案例库”；归档后显示闭环结论和完整复盘时间线。

## 模块边界

- `js/warning-demo-state.mjs`：状态枚举、迁移、校验、动作约束、`localStorage` 持久化和跨标签页 `storage` 通知。
- `js/warning-demo-media.mjs`：IndexedDB 图片保存、读取和删除，不处理业务状态。
- `js/warning-demo-ui.js`：三端 DOM 渲染、表单校验、弹窗/抽屉、时间线和事件动作绑定。
- `server/roof-risk-repository.js`：提供基于真实标准化特征的相似案例查询，不保存演示业务状态。
- `server.js`：新增只读相似案例 API，沿用认证和错误响应约定。

## 视觉方向

- 延续现有煤矿驾驶舱基调；橙色仅用于本次较大风险和当前动作，蓝色用于数据来源，绿色用于核验通过，红色仅用于驳回或重大风险。
- 事件状态采用一条七阶段工序轨道，形态参考井下运输调度线路，节点表达真实顺序而非装饰编号。
- 预警弹窗只在企业端首次触发时出现一次；之后使用顶部状态条和处置抽屉，避免覆盖 Three.js 或造成卡片重叠。
- 所有数值使用等宽数字，照片和工单作为证据区，不把页面堆成额外大屏。
- 1366×768 Chrome 首屏无横向溢出、弹窗不超出视口；移动宽度下抽屉改为全屏纵向布局。

## 异常与恢复

- 无法读取真实数据 API：禁止启动演示并说明“真实预警样本暂不可用”。
- 图片超限或格式不支持：保留已填写表单并给出具体错误。
- IndexedDB 不可用：允许工单继续填写，但禁止提交并提示照片存储不可用。
- DeepSeek 失败：使用现有本地专家规则并显示回退来源，不中断闭环。
- 刷新、退出登录或切换账号：从本地状态恢复当前事件和照片。
- 需要重新演示时：企业端“重置演示”只清除本演示事件及其图片，经二次确认后回到 `ready`。

## 测试与验收

- 单元测试覆盖七种状态、允许/禁止动作、数据迁移、表单要求和相似案例算法。
- DOM 合约测试覆盖三端所需容器、按钮和可访问标签。
- Chrome 自动化走通：企业触发并提交 → 监管驳回 → 企业复提 → 监管通过 → 智库生成建议并归档。
- 每次切换账号后状态、工单、照片数、监管意见和时间线保持一致。
- 相似案例均能追溯到老师数据集中的真实记录；预警与对照记录显示 SHA-256 来源标识。
- 全量现有测试通过，企业端 Three.js 不因演示状态更新而重新初始化或跳动。

## 不在本期范围

- 不实现不同电脑间实时同步。
- 不把演示照片上传到 Supabase Storage。
- 不声称后续真实记录是补强支护导致的实际结果。
- 不增加新的模型训练或改变现有 XGBoost 输出。
