# 教师审查快速指南

## 一、推荐入口

- 系统登录：`https://smart-mine-v2-balanced.vercel.app/login`
- 后端健康检查：`https://smart-mine-v2-balanced.onrender.com/healthz`
- GitHub 源码：`https://github.com/kenanxin/smart-mine-digital-twin`

演示账号由项目组使用私密账户卡现场提供。公开文档和 GitHub 不保存生产密码。

## 二、三分钟检查重点

1. 企业端：查看井下数字孪生、真实监测记录、三类风险场和六阶段灾变演示。
2. 监管端：查看区域态势、风险事件、监管督办和归档权限。
3. 智库端：查看 XGBoost 四级概率、特征证据、真实标签、预测标签和模型指标。
4. 只读端：确认复用智库端信息布局，但没有写操作。
5. 超级管理员：确认可创建账户、分配角色、停用账户、重置密码和查看审计日志。

## 三、真实数据证据

- 原始数据：`data/teacher_roof_monitoring.csv`
- 数据规模：20,000 行、11 列。
- SHA-256：`86D4C2FB192721B2745F00076AEB00CF351C654ED936DDB098BFA6217E30AC6A`
- 类别分布：低风险 7,432；一般风险 9,830；较大风险 2,071；重大风险 667。
- 模型：XGBoost；独立测试准确率 99.325%，全量回放一致率 99.665%。
- 运行数据：`data/roof-risk-dataset.json`，由卡尔曼平滑、标准化和模型推理流程确定性生成。

## 四、部署架构

```text
浏览器
  -> Vercel：静态页面、Three.js、ECharts
  -> Render：Node API、会话、权限校验、RoofRisk 业务
  -> Supabase：Auth、角色、权限、账户状态、审计日志
```

前端不持有 Supabase Service Role Key；管理员能力只在 Render 后端执行。前端隐藏按钮不是唯一保护，后端会再次校验角色权限。

## 五、故障预案

- 登录页能打开但认证暂不可用：先访问健康检查，等待 Render 冷启动完成后重试。
- 已登录后突然回到登录页：Render 重启使内存会话失效，重新登录即可。
- 现场网络不可用：在源码目录设置 `PORT=8092` 后执行 `npm start`，打开 `http://localhost:8092/login`。
- 三维画面未出现：刷新页面并确认浏览器启用硬件加速；仍异常时使用 Chrome 或 Edge 最新版。

## 六、答辩边界

- 当前平台已接入老师真实 CSV 和现有 XGBoost 模型的构建期推理结果，不应描述为随机模拟数据。
- 六阶段灾变过程是可重复的演示模式，用于说明监测、预警、处置和复盘闭环。
- Supabase 已用于身份与权限数据持久化；高频实时传感器流可继续按 RoofRisk API v1 接入。
